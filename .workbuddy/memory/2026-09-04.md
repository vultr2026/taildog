## 浏览器 ERR_FAILED 修复（CORS 预检）

浏览器实测发现：访问 `http://127.0.0.1:8787/healthz` 抛 `net::ERR_FAILED`，而 curl 正常。根因：客户端 `apiFetch` 给每个请求加了 `ngrok-skip-browser-warning` 自定义头，触发 CORS OPTIONS 预检；但服务端 `corsHeaders` 只声明 `access-control-allow-headers: content-type`，预检拒绝 → 实际请求被拦。

修复：`server/src/index.mjs` 的 `corsHeaders` 改为 `"access-control-allow-headers": "*"`（API 无认证、无敏感头，安全可接受；ngrok-skip-browser-warning 是绕过 ngrok interstitial 必需的）。

部署注意：源码已修，但当前 8787 上跑的是隐藏的旧实例（sandbox 工具看不到也 kill 不了），需用户本人在终端结束旧进程后重启才会生效。已在 8788 用修复版 + 隔离 DB（taildog-8788.db）临时起一个供调试；客户端 App 把 Server address 改成 `http://127.0.0.1:8788` 即可立即可用。

## APK 打包（Taildog 0.4.0）

**目标**：产出真实可安装的 Android APK 替代占位的 0.3.1。

### 环境（已确认可用）
- **JDK 21 必备**：本机默认 JDK 17 不够（Capacitor 8 `compileOptions VERSION_21`）。临时解决：下载 Oracle openjdk 21+35 portable 到 `C:/Users/Administrator/AppData/Local/Temp/jdk21/extracted/jdk-21`，设置 `JAVA_HOME` 指向该路径。
- **Gradle 8.14.3 通过 Tencent 镜像预下载到 wrapper 缓存**：因 services.gradle.org 直连 10 秒超时且 SSL reset。`~/.gradle/wrapper/dists/gradle-8.14.3-all/<hash>/gradle-8.14.3-all.zip` 由 curl 走 `https://mirrors.cloud.tencent.com/gradle/gradle-8.14.3-all.zip` 下载后 `unzip` 解出 `gradle-8.14.3/bin/`。`gradle/wrapper/gradle-wrapper.properties` 中 `networkTimeout=600000`。
- **Android SDK**：本地 `D:/android-sdk`（`platforms/android-36`、`build-tools/36.0.0`、`cmdline-tools/latest`、`licenses/` 已接受）。`local.properties` 已指向 `sdk.dir=D:/android-sdk`，无需改。
- **JAVA_HOME/ANDROID_HOME**：CI/Shell 一行：
  ```
  export JAVA_HOME="C:/Users/Administrator/AppData/Local/Temp/jdk21/extracted/jdk-21"
  export ANDROID_HOME="D:/android-sdk" && export ANDROID_SDK_ROOT="D:/android-sdk"
  export PATH="$JAVA_HOME/bin:$ANDROID_HOME/cmdline-tools/latest/bin:$ANDROID_HOME/platform-tools:$PATH"
  ```

### `cap sync android` 故障 + 旁路
sandbox 里 `cap sync android` 在 "Updating Android plugins" 阶段必抛 `safe-delete ETIMEDOUT`（调用 `D:/WorkBuddy/resources/vendor/genie-trash/win32-x64.exe` 失败）。但前两个 step（copy assets / 生成 capacitor.config.json）已成功，`capacitor.plugins.json=[]`。后续缺文件可手工从 `node_modules/@capacitor/cli/assets/capacitor-cordova-android-plugins.tar.gz` 模板解出：
```
capacitor-cordova-android-plugins/
  build.gradle                    (Android library 模块)
  cordova.variables.gradle        (// DO NOT EDIT, 包含 cdvPluginPostBuildExtras = [])
  src/main/AndroidManifest.xml    (空 manifest)
  src/main/java/.gitkeep
  src/main/res/.gitkeep
```
并把 `apply from: "cordova.variables.gradle"` 插到模板的 `// PLUGIN GRADLE EXTENSIONS START/END` 之间（cap sync 通常由 cap update 注入，沙箱没跑通所以手动补）。
